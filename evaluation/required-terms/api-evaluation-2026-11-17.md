실제 API가 8항목 코드와 `document_presence`를 **명시적으로 반환한 것은 10/32개**(31.3%)이며, 이 10개는 정답 초안과 일치했다. 나머지 22개에는 항목별 상태가 없다. `DISCOVERED_MISSING`처럼 항목 코드가 없는 추가 발견은 8항목 채점에 넣지 않았다.

## 확인된 문제

1. 현재 `.env`의 `dense_bm25_top5` 설정은 RAG 로딩 시 `BM25 인덱스와 질의 토큰화 설정·버전이 다릅니다`로 실패했다. 설정 그대로 첫 API job은 `RAG_UNAVAILABLE`였다. 위 점수는 **실행 프로세스에서만 `CHECKIT_RAG_METHOD=dense`로 바꿔** 얻었다. 설정된 검색 방식의 성능 점수로 사용하면 안 된다.
2. C04에서 부속합의서 A가 제출됐는지 모르는 임금 지급·연차·업무 3항목의 `UNCLEAR`를 항목별로 반환하지 않았다. 추가 발견 1개는 `check_code=DISCOVERED_MISSING`, `document_presence=null`이라 어느 항목을 보류한 것인지 기계적으로 연결할 수 없다.
3. C01·C03의 임금 지급은 문서에 기재됐는데도 규칙의 누락 후보로 올라왔고, 최종 `document_presence=PRESENT`로 정정됐다. C03에서는 계산 방법이 적힌 문구에 대해 별도 `DISCOVERED_ISSUE`가 계산 방법 부족을 주장했다. 최종 상태·설명의 품질은 8항목 기재 점수와 따로 검토해야 한다.

## 누락 후보 원인 추적

같은 고정 버전 분류기로 4개 계약서의 조항 라벨을 다시 추론하고, `analysis_rules.REQUIRED`의 문구 패턴과 후보 생성 조건을 재현했다. 규칙은 **문서 전체의 해당 분류 라벨이 없거나, 해당 항목의 문구 패턴이 없으면** `MISSING_*` 후보를 만든다. 후보는 Gemini 검토 후에야 최종 `document_presence`가 정해진다.

| 사례 | 실제 입력과 재현 결과 | 원인·최종 결과 |
| --- | --- | --- |
| C01·C03 임금 지급 | 두 지급 조항 모두 분류 라벨은 `임금`. `매월 말일에/25일에 … 계좌로 이체`는 지급 규칙의 문구 패턴에 걸리지 않음 | 규칙이 잘못된 누락 **후보**를 만듦. Gemini가 둘 다 `PRESENT`로 바로잡음 |
| C02 실제 누락 4개 | 임금 계산·지급·휴일·취업 장소 문구가 전체 계약서에 없음 | 각각 `ABSENT`로 반환. 분류 오류로 생긴 거짓 누락이 아님 |
| C03 실제 누락 4개 | 임금 구성·소정근로시간·연차·업무의 내용이 없음 | 각각 `ABSENT`로 반환. `실제 근로시간` 때문에 소정근로시간 문구 패턴만은 참이었지만, 분류 라벨 `근로시간`이 없어서 후보가 생성됨 |
| C04 판단 불가 3개 | 지급·연차·업무 조항이 모두 `부속합의서 A`를 참조함. 각 조항은 해당 분류 라벨과 문구 패턴을 모두 충족 | `MISSING_*` 후보 자체가 없고 항목별 `UNCLEAR`가 반환되지 않음. 코드가 없는 추가 발견 1개만 남음 |

따라서 이번 사례에서 정상 지급 조항의 오탐 후보 원인은 **분류기보다 지급 문구 패턴**이다. C04의 미검출 원인은 부속 문서 참조를 내용 확인으로 취급하는 후보 생성 조건과 8항목 전체를 결과로 내보내지 않는 응답 구조다.

평가에 만든 계약서와 가상 계정은 삭제했다. 이 4건은 합성 소표본이고 정답도 전문가 미검토이므로, 수치는 제품 전체 정확도나 법률 판단 정확도를 추정하지 않는다.
