# 조항 분류 데이터·서비스 연계 계획

작성일: 2026-10-21. 사용자가 제공한 데이터 수집·전처리 계획을 정리한 문서입니다. 데이터 파일·전처리 코드·모델 산출물을 직접 검증한 결과가 아닙니다. 원자료에는 계획과 수행 결과 형식의 서술이 함께 있어, 수치와 완료 여부는 산출물로 확인해야 합니다.

## 1. 데이터 범위

| 구분 | 문서 수 | 조항·라벨 수(제공 자료 기준) | 용도 |
| --- | ---: | ---: | --- |
| 근로 관련 TL | 190 | 약 10,200 | 학습 90%·검증 10% |
| 근로 관련 VL | 25 | 약 1,100 | 최종 평가 전용 |
| 기타고용계약서 TL+VL | 379 | 약 5,400 | 선별 후 학습 보강 |
| 기타인사노무 TL+VL | 436 | 약 840 | 선별 후 학습 보강 |

- 핵심 문서: 근로(고용)·아르바이트·연봉계약서 215건.
- 사용자 선택으로 원래의 TL/VL 구분을 유지합니다. TL에서 학습 90%·검증 10%를 나누고, 근로 관련 VL은 최종 평가에 사용합니다. 양식 그룹 재분할은 채택하지 않습니다.
- 기타 문서에서 조항을 가져오는 것은 학습 보강입니다. 서비스가 기타 문서 전체를 지원한다는 확정이 아닙니다.

## 2. 10개 분류 라벨

아래 순서는 제공 자료의 표시 순서입니다. 실제 모델 출력 순서는 최종 `labels.json`을 기준으로 고정해야 합니다.

| 라벨 | 포함 내용 | 서비스 연계 계획 |
| --- | --- | --- |
| 임금 | 금액·수당·상여금·지급일·지급 방법 | 기재 여부·세부 값 추출·관련 법령 검색 |
| 근로시간 | 근무 요일·시간·휴게시간 | 기재 여부·시간 추출·변경 조건 검토 |
| 휴일 | 주휴일·쉬는 날 | 기재 여부·관련 법령 검색 |
| 휴가 | 연차유급휴가 등 | 기재 여부·문구 구체성 검토 |
| 근무 장소·업무 | 장소·담당 업무·변경 | 기재 여부·변경 조건 검토 |
| 계약기간 | 시작·종료·수습 기간 | 기간 추출·적용 조건 확인 |
| 계약 종료 | 해지·해고·퇴직 절차 | 종료 조건 검토 |
| 손해배상·위약금 | 퇴사·위반 시 금전 부담 | 주의 조항 검토 |
| 기타 근로조건 | 퇴직금·사회보험·비밀유지·경업 및 겸직 제한 | 참고 표시·지원 규칙이 있는 항목 검토 |
| 그 외 | 제목·서문·날짜·서명·인적사항·준거법·관할 등 | 현재 분류 계획에서는 내용 판정 제외, 원문 연결 |

- 한 조항에 여러 라벨을 허용합니다. `labels`와 길이 10의 `label_vec`를 사용합니다.
- 원래 라벨을 `label_map.json`으로 변환합니다. 날짜·서명은 ‘그 외’로 처리하며, 내용 라벨과 원래의 ‘기타’가 함께 있으면 ‘기타’를 버리는 규칙을 기록합니다.
- 라벨 이름·순서·매핑·전처리·임계값을 모델 버전과 함께 관리해야 합니다.
- 원자료의 법령 매핑은 검색 후보 설계안입니다. 조문 원문·시행일·적용 조건 검수 전에는 확정 판정 규칙으로 사용하지 않습니다.
- ‘그 외’ 분류는 개인정보를 삭제했다는 의미가 아닙니다. 해당 텍스트에도 인적사항 등이 남을 수 있습니다.

## 3. 전처리 계획

- HTML 표를 항목과 값의 관계를 보존한 텍스트로 펼칩니다.
- 벌려 쓴 제목의 글자, 연속 공백·탭·빈 줄, 유니코드 NFC를 정규화합니다.
- 날짜 빈칸과 미기입 표시를 보존합니다. 가명 표기를 통일하고 `(@회사명)` 같은 변수는 `[회사명]` 형태로 바꿉니다.
- 학습 자료의 예시 금액을 `○원`으로 바꾸는 규칙이 제시돼 있습니다. 실제 금액 판정용 입력에 동일하게 적용하지 않도록 분리 설계가 필요합니다.
- 짧은 하위 항목에는 상위 조 제목을 붙입니다.
- 형태소 분석·불용어 제거·문장부호 및 숫자 일괄 제거·자동 맞춤법 교정은 하지 않습니다.

서비스 입력은 다음 표현을 구분하도록 설계합니다.

1. 원본 및 OCR 추출 텍스트와 페이지·영역 좌표.
2. 사용자가 확인·수정한 텍스트와 원본 연결 정보.
3. 분류 모델 입력용 전처리 텍스트.
4. 금액·시간·날짜 등 실제 값 추출 및 판정에 사용하는 텍스트.

분류에는 학습과 서비스에서 같은 버전의 전처리를 사용하되, 분류용 치환 결과로 원본·사용자 수정본을 덮어쓰지 않습니다. 공백 정리·제목 추가·사용자 수정 후에도 원본 영역과의 연결이 유지돼야 합니다.

## 4. 확정된 분할 방식과 학습·평가 계획

- 근로 관련 TL 190문서에서 학습 90%·검증 10%를 나누고, 근로 관련 VL 25문서는 최종 평가에만 사용합니다. 실제 전처리 후 문장 수는 다시 집계합니다.
- TL 내부 분할 단위·시드·중복 처리 기준은 구현 시 정합니다. 같은 문서의 조항이 학습·검증 양쪽에 흩어지지 않도록 문서 단위 분할을 제안합니다.
- core는 핵심 문서만, all은 기타 문서에서 선별한 조항을 추가합니다. 같은 핵심 검증 데이터와 근로 관련 VL 평가 데이터로 비교합니다.
- 기타 문서의 TL+VL 활용은 제공 자료의 학습 보강 계획입니다. 근로 관련 VL 평가 데이터와는 구분하고, 검증·평가 데이터와 중복되는지 점검합니다.
- 출력은 라벨별 sigmoid, 손실은 BCE 계열, 불균형 보정은 학습 데이터에서 구한 `pos_weight`를 후보로 합니다.
- 라벨별 threshold와 모델 설정은 TL 내부 검증 데이터로 선택하며, VL로 조정하지 않습니다.
- 라벨별 F1·precision·recall, micro/macro F1을 기록합니다. 누락 탐지에 사용하는 항목은 recall을 중점 확인합니다.
- 모델·설정 고정 후 VL로 최종 평가합니다.
- 원자료에는 VL 25문서 중 16문서가 TL과 비슷한 양식이라는 설명이 있습니다. 선택한 TL/VL 분할은 유지하되 양식·문장 중복 정도와 평가 해석의 한계를 함께 기록합니다.
- `max_length=256`은 후보 설정입니다. 문자 수만으로 충분하다고 확정하지 않고 실제 토크나이저의 토큰 길이·절단 비율로 검증합니다.

### 채택하지 않은 이전 분할안과 통계

- 양식 유사도 60% 기준으로 215문서를 76그룹으로 묶고, 18그룹·42문서·1,103문장을 test로 사용하는 안은 채택하지 않습니다.
- 나머지 데이터의 그룹 5-fold와 `fold=-1` 처리도 현재 확정 방식의 요구사항이 아닙니다.
- 기존 core train 3,900문장·all train 6,897문장·test 1,103문장과 동일 test 문장 145개는 이전 분할안에 제시된 수치입니다. 현재 TL/VL 분할의 확정 수치로 사용하지 않고 재집계합니다.

## 5. 백엔드 연결 방향

- AI 레포의 서비스용 코드를 Python 패키지로 구성해 백엔드 실행 환경에 설치하고 호출하는 방식으로 확정했습니다. 학습·전처리 코드는 서비스 추론 코드와 분리하며, 모델 파일·법령 인덱스는 별도로 준비합니다. 레포의 실제 이전이나 패키지 생성은 아직 수행하지 않았습니다.

사용자 확인 텍스트 → 조항 분리·제목 연결 → 다중 라벨 분류 → 세부 항목·값 추출 → 관련 법령 검색 → 적용 조건 확인 → 결과·근거·원본 위치 저장.

- 라벨은 점검 주제와 검색 후보를 고르는 신호이며 위험 판정 결과가 아닙니다.
- ‘임금’ 라벨이 있다고 지급일·금액·지급 방법이 모두 기재된 것으로 판단하지 않습니다. 세부 항목별 존재·빈칸·추출 실패를 구분합니다.
- 라벨이 검출되지 않은 경우도 바로 누락으로 단정하지 않습니다. OCR·분류 실패와 실제 미기재를 구분하고 미확인 상태를 지원합니다.
- 라벨로 연결 법령을 우선 검색하되, 오분류 때문에 근거를 영구적으로 제외하지 않도록 검색 범위 확대 경로를 설계합니다.
- 확신이 낮으면 LLM 보완을 후보로 검토합니다. LLM 출력도 검증 대상으로 두고 해결하지 못하면 추가 확인 상태를 반환합니다.
- 현재 RAG의 근로기준법 외에 최저임금법·기간제법·시행령·퇴직급여 관련 법령 등이 필요할 수 있습니다. 원자료의 판정 목표를 모두 구현하려면 법령 범위 확대와 별도 검수가 필요합니다.
- 현재 자료의 평가 계획은 조항 분류 평가입니다. 누락 탐지·법령 검색·적용 조건 판단·최종 설명은 각각 검증해야 합니다.
- 10개 분류 라벨 지원과 각 라벨의 모든 법률 쟁점 자동 판정 지원은 구분합니다. 실제 첫 버전 점검 규칙 목록은 아직 미정입니다.

## 6. 산출물·취급 계획

| 파일 | 내용 |
| --- | --- |
| `train.jsonl` | TL 학습 데이터. `text`, `labels`, `label_vec`, `doc_type`, `source` 등. 이전 `fold`·`group` 필드의 유지 여부는 미정 |
| `validation.jsonl` | TL에서 분리한 검증 데이터. 파일명은 제안 |
| `test.jsonl` | 근로 관련 VL 기반 고정 최종 평가 데이터 |
| `labels.json` | 모델 출력 라벨 순서 |
| `label_map.json` | 원래 라벨과 서비스 라벨의 매핑 |
| `stats.md` | 전처리·분할 통계 |
| `unmapped_labels.csv` | 매핑하지 못한 라벨 |

- `processed_core/`, `processed_all/`로 기본·비교 데이터 산출물을 구분합니다.
- 원자료와 가공 데이터는 팀 드라이브에서 관리하고 GitHub에는 올리지 않는다는 사용자 제공 방침을 따릅니다. 원자료의 재배포 제한에 대한 설명을 기록한 것이며 이용약관을 직접 검증한 것은 아닙니다.
- 데이터 수집·전처리·학습은 데이터 영역에서 관리하고, `CheckIt_BE`에는 서비스 연계 설계와 추론 연결 코드를 둡니다. 본 작업에서는 데이터 파일을 복사하거나 학습을 실행하지 않았습니다.

## 7. 확인이 필요한 사항

- TL/VL 유지 방식은 확정됐습니다. TL 내부 분할 단위·시드·중복 처리 기준은 미정입니다.
- 약 16,000개, 추가 내용 조항 5,893개·‘그 외’ 1,767개, 최종 train 수치는 단계·중복 제거·라벨 집계 단위가 다를 수 있습니다. 단계별 통계 산출물로 대조가 필요합니다.
- 분류 모델 학습 완료 여부·성능·선택 모델은 제공 자료만으로 확인되지 않았습니다.
- 근로계약서 외 실제 지원 계약서 유형은 여전히 미정입니다.
